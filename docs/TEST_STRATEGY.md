# Test Strategy

Implements PRD section 12.8 and the acceptance criteria in section 28.

## 1. What can and cannot be tested today

| Layer | Status | Why |
|---|---|---|
| Configuration schema and referential integrity | **Executing** | Offline |
| Lifecycle, routing, review, integrity, ID rules | **Executing** | Pure functions, no tenant |
| Safety gates (production, retention, irreversible controls) | **Executing** | Offline |
| Plan/Apply behaviour and determinism | **Executing** | Plan needs no tenant |
| Cmdlet fabrication guard | **Executing** | Verified against committed PnP source index |
| Provisioning against a tenant | **Pending** | No connection or credentials |
| Workflow execution | **Pending** | No Power Platform environment |
| Security role access | **Pending** | Groups do not exist |
| Purview retention | **Blocked** | OQ-03 unanswered |
| Accessibility | **Pending** | No deployed UI |
| Performance, migration, recovery | **Pending** | No tenant |

Pending tests are **written or specified**, not skipped silently.

control · routing resolution including ambiguity and separation of duties · effective-revision

### Data (partly executing)

### Recovery (specified, pending backup decision — OQ-06)

reconciliation · RPO/RTO measurement · failed-restore escalation.

## 4. Tests that exist to catch our own mistakes

Three deserve specific mention because they guard against plausible-looking errors:

- **Fabricated cmdlet detection.** Two tests deliberately feed the validator a non-existent cmdlet
  and a non-existent parameter and assert it catches both. Without these, the guard could silently
  stop working and nobody would notice.
- **No invented retention period.** Asserts every period is still `REQUIRES_RECORDS_APPROVAL`.
  Prevents a future edit from quietly inserting a legal retention period nobody approved.
- **Discovery is read-only.** Parses `Invoke-DmsDiscovery.ps1` and fails if any mutating PnP cmdlet
  appears, so a discovery script cannot drift into changing tenant state.

## 5. Traceability

`docs/REQUIREMENTS_TRACEABILITY.md` is generated by scanning the PRD for requirement IDs and locating
each across configuration, code, specifications and tests. A requirement referenced by code but not
by a test is classified "Implemented, tenant validation pending" — the classification cannot be
inflated by hand.

## 6. Entry and exit criteria

**Entry to tenant testing:** offline suite green · configuration validation passes · connection
available · Entra groups created · production guard satisfied for the target environment.

**Exit for MVP** (PRD 12.9): all P0 accepted · ≥20 documents through the full lifecycle including one
rejection and one supersession · 100% metadata and evidence reconciliation · ≥90% findability ·
≥99% workflow success after stabilisation · no unresolved Critical or High security defect · recovery
test meets approved RPO/RTO · sign-off by Product Owner, Document Control, Records Management,
Security and the pilot business owner.
